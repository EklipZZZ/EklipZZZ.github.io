## 2. 复现对象与推理链

### 2.1 Training-free 约束

本轮采用严格的 training-free 推理：

- 不在水下数据上训练、微调或更新模型参数；
- 使用官方 OpenCLIP LAION-2B 权重和 DepthAnything-V2；
- MLLM 只读取作者提供的离线 JSON 描述，不在运行时调用 GPT-4o 或其他 API；
- 代码、环境、数据、权重和结果分开放置；
- 每次正式运行记录代码 HEAD、环境、权重、数据、配置、硬件和指标。

这里的 `use_mllm` 只是读取缓存的描述文件，不代表运行时调用 MLLM 服务。

### 2.2 E2O 的代码路径

1. 输入水下图像，用冻结的 OpenCLIP 提取密集视觉特征。
2. 用 DepthAnything-V2 等几何视觉特征计算空间关系，GMG 将几何关系转成视觉特征传播/修正权重。
3. 用类别名称和水下 prompt 生成类别文本特征；如果打开 MLLM，则读取离线描述，再编码并与类别文本特征融合，形成 CSA 文本分支。
4. 计算修正后的视觉特征与融合后文本特征的相似度，reshape 成类别预测图并评估。

GMG 主要作用在视觉分支，CSA 主要作用在文本分支。本轮代码没有在水下样本上学习新的适配器或分类头。

### 5.2 Aqua 评估语义审计

Aqua mask 为 16-bit，背景值是 65535；当前 MMSegmentation `IoUMetric` 默认 `ignore_index=255`。因此，不额外映射时，65535 不会按默认忽略值处理。

**Evidence：** ViT-B/16 的 Aqua mIoU 为 17.82，论文为 17.81，当前发布代码行为已经复现主结果。

**当前处理：** 主复现继续保留 released metric 行为，不优先进行双评分。

**后续需要时：** 复制 mask，另外计算将 65535 映射到 255 的 corrected metric；不能覆盖原始标注，也不能把两种口径混在同一张主表里。

本地保留 19 个 UOVSBench ZIP 分卷；先前审计记录的大小和 SHA256 与 Hugging Face `kkk2026/UOVSBench` 对应快照一致，远端快照标识记录为 `a77f1c9...`。正式投稿前仍需把完整远端 commit 和每个 ZIP 哈希写入 manifest。

## 8. H/14-USIS16K 的 MLLM 判别实验

### 8.1 实验问题

同一数据、权重、GMG、模板和主参数下，为什么使用开源 GPT-4o JSON 得到 52.31，而论文表格是 45.68？

### 8.2 固定 200 图筛查

四组使用完全相同的 deterministic subset，清单 SHA256 为：

`24FF0CD61C3CE7E8CDEBCF4DC16B2119EF81ADEE06E4A8FCDE9C16834148AFDB`

| MLLM 条件 | aAcc | mIoU | mAcc |
|---|---:|---:|---:|
| 无 MLLM | 60.76 | 44.14 | 62.50 |
| GPT-4o JSON | 65.87 | 49.72 | 66.05 |
| Qwen2.5VL-3B JSON | 59.45 | 42.26 | 60.18 |
| Qwen2.5VL-7B JSON | 61.64 | 44.37 | 62.41 |

### 8.3 全量确认

| 条件 | 图像数 | aAcc | mIoU | mAcc |
|---|---:|---:|---:|---:|
| 论文 H/14 + USIS16K | 16,151 | 60.45 | 45.68 | 59.99 |
| 本次 GPT-4o JSON | 16,151 | 66.22 | 52.31 | 65.65 |
| 本次关闭 MLLM | 16,151 | 60.40 | 45.64 | 59.95 |

**Evidence：** 相同数据和权重下，切换 MLLM 会同时改变 aAcc、mIoU、mAcc；关闭 MLLM 后三个指标分别只差论文约 -0.05、-0.04、-0.04。固定 200 图也复现同方向效应，因此不是抽样噪声可以解释的。

**Inference：** 论文 H/14-USIS16K 的 45.68 最可能对应 MLLM 未启用、未生效，或使用了等价的非 MLLM 运行口径。

**待核对：** 目前仍不能确定是表格记录错误、JSON 当时为空/不匹配、CLI 漏传参数，还是其他等价 bug；也不能据此断定其他 H/14 数据集存在同样混用。

论文超参数消融中存在正文和表格不完全一致的地方：

- `beta`：正文默认 1.2，论文主结果 mIoU 34.32；
- `gamma`：正文称 3.0 最优，但表中 mIoU 在 1.0 时最高，为 34.44，aAcc 和 mAcc 在 2.0 时最高；
- `wmax`：正文称 0.5 最优，但表中 0.8 的三个指标更高，为 54.65/34.62/50.01；
- `tau`：0.1、0.2、0.3 在表中四舍五入后并列；发布主配置和当前运行使用 0.5，对应 mIoU 34.32。

论文正文“beta=1.2、gamma=3.0、wmax=0.5、tau=0.1 为最优”与表格数值并不完全一致。后续复现需要明确采用哪一种口径，并在实验记录中固定下来。

## 11. 可复现性判定

### 11.1 Evidence

- B/16 六个数据集逐项接近论文值，平均 mIoU 与论文相同；
- H/14 五个数据集逐项接近论文值，说明 H 权重和主推理链路正常；
- H/14-USIS16K 关闭 MLLM 后可复现论文数值，打开 GPT-4o JSON 后稳定升高到 52.31；
- L/14 的官方归一化可以解释一部分偏差，但平均值仍为 42.38，未达到论文 44.00。

### 11.2 Inference

- 当前最可靠的稳定基线是 B/16 + released normalization；
- H/14-USIS16K 的异常主要来自 MLLM 设置差异；
- L/14 的剩余偏差需要更多配置、checkpoint 和 preprocessing 信息才能定位。

### 11.3 判定边界

这里比较的是确定性全量 benchmark 指标，不做统计显著性检验，也不把单次 mIoU 差异包装成 p-value。后续自己的方法比较应至少报告多数据集结果、按类别差异，并在需要时使用 bootstrap 图像/类别置信区间。
