# E2O 水下提示词库

本页整理自 E2O 补充材料中的 prompt templates。`{class}` 是待替换的类别名，例如 `zebrafish`、`coral reef` 或数据集中的规范类别名称。

## 使用原则

对类别 $c_t$ 和模板 $p$，冻结 CLIP 文本编码器产生多个 embedding，再对同一类别求平均：

$$
E_t=\frac1P\sum_{p=1}^{P}
\mathrm{TextEncoder}\bigl(p({c_t})\bigr).
$$

这一步是 prompt ensemble，不是参数训练。为了做可靠消融，建议保留以下字段：

- `prompt_bank_version`
- 使用的模板类别（基础/场景/成像/交互/外观/环境）
- 每个类别的原始名称和清洗后的名称
- 文本编码器与 checkpoint
- 是否做 L2 normalization、平均前还是平均后归一化

不要默认把所有模板混合后就称为“水下 prompt 有效”。至少要比较：通用 prompt、基础水下 prompt、场景 prompt、成像/退化 prompt、完整模板集。

## 7. 推荐的可控实验组合

| 组合 | 模板范围 | 目的 |
|---|---|---|
| P0 | `a photo of a {class}.` | 通用 CLIP baseline |
| P1 | Basic | 只测试“加入 underwater 词”的影响 |
| P2 | Basic + Scene | 测试水下栖息地上下文 |
| P3 | Basic + Imaging | 测试颜色衰减、浑浊、散射和模糊语义 |
| P4 | Basic + Scene + Appearance + Environment | 测试外观/场景组合 |
| P5 | 全部模板 | 论文式完整 prompt ensemble，成本和冗余最高 |

**Hypothesis**：对于水下 OVSS，`P3` 可能更直接覆盖域退化，`P2/P4` 可能更有利于类别—环境语义对齐；这一假设需通过消融实验检验。

## 8. 与 MLLM 描述的配合

静态模板回答“这个类别在典型水下场景中如何被描述”；MLLM 描述回答“当前图像中可能出现什么对象、具有什么属性”。二者在 E2O 中应分别记录：

$$
E_t=\text{类别 + 水下模板的文本原型},
\qquad
E_r=\text{MLLM 生成描述再经 CLIP text encoder 的语义方向}.
$$

MLLM 的自由文本应与类别字符串、原始输出一起保存。正式实验至少保存：

- MLLM 名称和版本；
- 生成 prompt；
- 原始 JSON/文本；
- 类别约束是否被遵守；
- CLIP 文本编码结果的缓存版本；
- 生成时间和是否使用在线图像条件推理。
