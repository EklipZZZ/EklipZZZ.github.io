# DeCLIP：论文整理版

> [!summary] 一句话概括
> DeCLIP 不是在每张测试图像上临时修补 CLIP，而是先用无标签图像对 CLIP 视觉编码器做一次无监督微调：把最后自注意力中的“上下文关系”和“局部内容”解耦，再分别用 VFM/扩散模型和裁剪图像的 [CLS] 表征进行蒸馏，最终得到一个更适合开放词汇密集感知的视觉骨干。

## 2. 论文究竟要解决什么问题？

### 2.1 CLIP 的强项是全局图文对齐

CLIP 的基本目标是让整张图像和对应文本靠近：

$$
I \longleftrightarrow t.
$$

视觉编码器中的 [CLS] token 汇总整张图像，文本编码器输出类别或描述的文本 embedding。这个机制很适合图像分类和全局图文检索，但开放词汇密集感知需要的是：

$$
\text{局部 patch 或区域}
\longleftrightarrow
\text{类别文本}.
$$

也就是说，模型不仅要知道图像里“有一只鸟”，还要让鸟所在的局部 token 具有可区分的鸟语义，并且同一只鸟内部的 token 具有连续、稳定的表示。

### 2.2 深层的 proxy token 现象
![Pasted image 20260903005230](/assets/images/obsidian/960971f02f5de99ebe34ef76973c0ef7.png)
论文比较了 CLIP 与 VFM 在不同层的注意力图。浅层 CLIP 的 token 还能较好地关注语义相关区域；进入深层后，很多图像 token 会集中关注少数几个特殊 token。论文把这些 token 称作 **proxy tokens**。

关键点是：

- proxy token 不是一种额外输入，也不是“global patch”这种新的 patch 类型；
- 它本来就是普通的图像 patch token，只是在深层注意力中被很多 token 共同关注；
- 它们像中继站一样汇总信息，使 [CLS] 能够形成全局视图；
- 但对 dense prediction 来说，所有位置都去看同几处 proxy token，会削弱位置之间原本应该存在的语义差异。

因此，所谓“patch 又局部、又出现全局注意力”并不矛盾：

$$
\text{patch 的输入身份是局部的}
\quad\neq\quad
\text{它在深层注意力中只看局部}.
$$

### 2.3 两种需要同时改善的能力

| 能力 | 直观含义 | DeCLIP 的对应分支 |
|---|---|---|
| Local discriminability，局部判别性 | 不同物体的局部 token 能分辨不同语义 | Content features + Content Distillation |
| Spatial consistency，空间一致性 | 同一物体内部的 token 相互关联，区域连续且边界较完整 | Context features + Context Distillation |

论文的关键判断不是“CLIP 没有语义”，而是 CLIP 最后阶段把全局分类所需的信息聚合方式，带来了 dense feature 的局部与空间问题。

## 3. 记号：embedding、patch token、Q、K、V 到底是什么？

设输入到最后一个注意力块的 token 序列为：

$$
\mathbf{X}
 =
\{\mathbf{x}_0,\mathbf{x}_1,\ldots,\mathbf{x}_{HW}\},
\qquad
\mathbf{x}_i\in\mathbb{R}^{1\times D}.
$$

其中：

- $\mathbf{x}_0$ 是 [CLS] token，表示整张图像；
- $\mathbf{x}_1,\ldots,\mathbf{x}_{HW}$ 是图像 patch token；
- $H\times W$ 是 patch 网格大小；
- 每个 token 都是一个向量，不是原图中的一个像素。

经过最后注意力块后，$\mathbf{Z}[0]$ 是全局图像 token，剩余 token 可以重排成 dense feature map：

$$
\mathbf{X}_{\mathrm{dense}}
 =
\operatorname{reshape}\left(\mathbf{Z}[1:HW]\right)
 \in \mathbb{R}^{C\times H\times W}.
$$

这里的 embedding 只是“编码器输出的向量表示”：

- global embedding：整张图像的一个汇总向量；
- patch embedding：某个 patch 位置的局部向量；
- dense embedding：保留所有 patch 位置的一组向量；
- text embedding：文本编码器输出的类别或描述向量。

### 3.1 普通 CLIP 最后注意力块

普通自注意力的投影为：

$$
\mathbf{Q}=\operatorname{Proj}_q(\mathbf{X}),
\qquad
\mathbf{K}=\operatorname{Proj}_k(\mathbf{X}),
\qquad
\mathbf{V}=\operatorname{Proj}_v(\mathbf{X}).
$$

由 $\mathbf{Q}$ 与 $\mathbf{K}$ 计算注意力权重：

$$
\operatorname{Attn}_{qk}
 =
\operatorname{SoftMax}
\left(
\frac{\mathbf{Q}\mathbf{K}^{\mathsf T}}{\sqrt{d}}
\right).
$$

然后用注意力权重对 $\mathbf{V}$ 加权求和：

$$
\mathbf{Y}
 =
\mathbf{X}
 +
\operatorname{Proj}
\left(
\operatorname{Attn}_{qk}\mathbf{V}
\right),
$$

再经过前馈网络：

$$
\mathbf{Z}
 =
\mathbf{Y}
 +
\operatorname{FFN}(\mathbf{Y}).
$$

在这里：

- $\mathbf{Q}$ 和 $\mathbf{K}$ 共同决定“谁和谁相关”；
- $\mathbf{V}$ 携带被聚合的内容；
- 注意力矩阵的一个元素表示某个 query token 对某个 key token 的权重；
- 输出 token 是对多个 value token 加权后的结果。

### 3.2 DeCLIP 的解耦注意力

DeCLIP 不再让同一个标准注意力输出同时承担两种蒸馏目标，而是把最后注意力块重写为：

$$
\mathbf{X}_{\mathrm{context}}
 =
\operatorname{Proj}_q(\mathbf{X}),
\qquad
\mathbf{V}
 =
\operatorname{Proj}_v(\mathbf{X}).
$$

接着只用 $\mathbf{X}_{\mathrm{context}}$ 自身计算关系：

$$
\operatorname{Attn}_{\mathrm{context}}
 =
\operatorname{SoftMax}
\left(
\frac{
\mathbf{X}_{\mathrm{context}}
\mathbf{X}_{\mathrm{context}}^{\mathsf T}
}{
\sqrt{d}
}
\right).
$$

最后用这张关系图聚合 $\mathbf{V}$：

$$
\mathbf{X}_{\mathrm{content}}
 =
\operatorname{Proj}
\left(
\operatorname{Attn}_{\mathrm{context}}\mathbf{V}
\right).
$$

这三式回答了此前对 $Q$、$K$、$V$ 的疑问：

- $\mathbf{X}_{\mathrm{context}}$ 来自 $Q$ 投影，主要承担“哪些 token 具有空间或语义关系”的判断；
- $\mathbf{V}$ 来自 value 投影，携带每个 token 的视觉内容；
- $\mathbf{X}_{\mathrm{content}}$ 是注意力聚合后的内容特征，不是类别标签；
- 类别仍然要在下游通过图像特征与文本 embedding 的相似度来判断。

因此不能简单说“$m$ 负责决定类别”。在 DeCLIP 这里，关系权重负责信息聚合，类别判定发生在后续的视觉—文本匹配。

### 3.3 为什么同一条链能得到两种能力？

DeCLIP 的“解耦”不是把图像切成两张图，也不是额外预测一个上下文类别，而是在同一输入 $\mathbf{X}$ 上构造两个用途不同的中间表示：

$$
\mathbf{X}
\rightarrow
\left\{
\mathbf{X}_{\mathrm{context}},
\mathbf{X}_{\mathrm{content}}
\right\}.
$$

简化理解为：$\mathbf{X}_{\mathrm{context}}$ 决定哪些位置互相参考，$\mathbf{V}$ 提供视觉内容，$\mathbf{X}_{\mathrm{content}}$ 是按关系聚合后的可匹配表示。

## 4. 总体训练流程：模块与公式匹配

![Pasted image 20260903005351](/assets/images/obsidian/cae428e51e3171b329b948605b6f7267.png)

图中中心是解耦注意力，左侧是 context distillation，右侧是 content distillation 与 RCC。对应的公式主线为：

$$
\begin{aligned}
&\text{图像 }I
\rightarrow
\left(
\mathbf{X}_{\mathrm{context}},
\mathbf{V},
\mathbf{X}_{\mathrm{content}}
\right),\\
&\mathbf{X}_{\mathrm{context}}
\rightarrow
\mathbf{S}^{\mathrm{CLIP}}
\xleftarrow{\mathrm{KL}}
\widehat{\mathbf{S}}^{\mathrm{VFM}}
\leftarrow
\left(
\mathbf{S}^{\mathrm{VFM}},
\widehat{\mathbf{A}}_{\mathrm{self}}
\right),\\
&\mathbf{X}_{\mathrm{content}}
\rightarrow
\text{region feature}
\xrightarrow{\text{crop [CLS] 对齐 + RCC}}
\mathcal{L}_{\mathrm{content}},\\
&\mathcal{L}_{\mathrm{total}}
 =
\mathcal{L}_{\mathrm{content}}
 +
\lambda\mathcal{L}_{\mathrm{context}}
\rightarrow
\text{更新学生视觉编码器}.
\end{aligned}
$$

因此，DeCLIP 的训练输入是无标签图像，教师网络只提供关系或区域语义参照，真正被更新的是学生 CLIP 视觉编码器。

## 5. Context Distillation：让相关区域重新建立关系

### 5.1 VFM 先提供语义亲和矩阵

VFM 对图像输出 dense features：

$$
\mathbf{X}_{\mathrm{dense}}^{\mathrm{VFM}}
\in
\mathbb{R}^{D\times HW}.
$$

对任意两个 patch token 计算余弦相似度，形成整张图像的语义亲和矩阵：

$$
\mathbf{S}^{\mathrm{VFM}}
 =
\cos
\left(
\left(\mathbf{X}_{\mathrm{dense}}^{\mathrm{VFM}}\right)^{\mathsf T},
\mathbf{X}_{\mathrm{dense}}^{\mathrm{VFM}}
\right)
\in
\mathbb{R}^{HW\times HW}.
$$

其中：

$$
\mathbf{S}_{ij}^{\mathrm{VFM}}
 =
\cos
\left(
\mathbf{x}_i^{\mathrm{VFM}},
\mathbf{x}_j^{\mathrm{VFM}}
\right).
$$

它表达的是：如果两个位置在 VFM 特征空间中相似，那么它们可能属于同一语义区域，应该在 context 表示中保持关联。

### 5.2 SD-GSC 为什么需要 Stable Diffusion？

VFM 的优势是语义相似性较可靠，但亲和图可能出现：

- 物体边界模糊；
- 同一物体内部出现空洞；
- 区域不够完整。

Stable Diffusion 的 U-Net self-attention 对轮廓和布局等高频结构更敏感，但它单独作为语义教师时可能把注意力放到错误的相关对象上。因此两者分工不同：

| 模型 | 擅长提供 | 不足 |
|---|---|---|
| VFM | 语义相关性、同类区域相似性 | 边界和内部完整性可能不足 |
| Stable Diffusion self-attention | 物体轮廓、布局和完整性线索 | 语义判别能力不如 VFM |

论文把同一张图像和空文本提示送入 Stable Diffusion，从 U-Net 的多个层和注意力头提取：

$$
\mathbf{A}_{\mathrm{self}}
\in
\mathbb{R}^{L\times HW\times HW}.
$$

将不同层和头的注意力矩阵按链式乘法融合：

$$
\widehat{\mathbf{A}}_{\mathrm{self}}
 =
\prod_{i=1}^{L}
\mathbf{A}_{\mathrm{self}}[i].
$$

再用它修正 VFM 的语义亲和矩阵：

$$
\widehat{\mathbf{S}}^{\mathrm{VFM}}
 =
\widehat{\mathbf{A}}_{\mathrm{self}}
\times
\mathbf{S}^{\mathrm{VFM}}.
$$

这里的 $\times$ 是矩阵乘法，不是逐元素 Hadamard 乘法。这个修正的直觉是：

$$
\text{VFM 的语义证据}
+
\text{SD 的边界与布局传播}
\rightarrow
\text{更完整的上下文教师信号}.
$$

论文还比较了直接蒸馏 SD attention、通道拼接等方案，结果 SD-GSC 更好，因为它保留了 VFM 的语义判别，同时借用 SD 的完整性线索。

### 5.3 Context loss

由 DeCLIP context 表示计算 CLIP 侧的相似度矩阵：

$$
\mathbf{S}^{\mathrm{CLIP}}
 =
\cos
\left(
\mathbf{X}_{\mathrm{context}}^{\mathsf T},
\mathbf{X}_{\mathrm{context}}
\right).
$$

对每一个 query 行进行 KL 散度对齐：

$$
\mathcal{L}_{\mathrm{context}}
 =
\frac{1}{HW}
\sum_{i=1}^{HW}
\operatorname{KL}
\left(
\widehat{\mathbf{S}}_{i,:}^{\mathrm{VFM}},
\mathbf{S}_{i,:}^{\mathrm{CLIP}}
\right).
$$

这一步不是直接把 VFM 的 feature 向量复制到 CLIP，而是让 CLIP 的 context 分支学习 VFM 所表达的 token-to-token 关系。

## 6. Content Distillation：让局部 token 更能区分语义

### 6.1 为什么要用 crop 的 [CLS]？

如果只把 VFM 的空间关系蒸馏给 CLIP，模型可能变得更平滑、更一致，但不一定更会区分不同物体。于是 DeCLIP 使用 CLIP 自己的全局图文能力作为内容教师。

具体做法：

1. 把原图随机划分为 $k=m\times n$ 个子区域；
2. 从原图裁剪出子图 $I'_1,\ldots,I'_k$；
3. 学生模型已经对整张图提取了 $\mathbf{X}_{\mathrm{content}}$；
4. 用 RoI Align 按照裁剪坐标提取学生侧区域特征；
5. 冻结的 CLIP 教师分别处理每张 crop，取对应的 [CLS] token；
6. 让学生区域特征与对应 crop 的 [CLS] 表示对齐。

随机划分方式为：

$$
k=m\times n,
\qquad
m,n\sim\operatorname{Uniform}\{1,2,\ldots,6\}.
$$

这不是给每个区域增加人工类别标签，而是利用“这张 crop 的全局语义表示”指导它在整图 feature map 中对应的局部区域。

### 6.2 区域特征的加权汇聚

第 $i$ 个学生区域经过 RoI Align 后得到：

$$
\mathbf{f}_i^s
\in
\mathbb{R}^{N^2\times C}.
$$

对应 crop 的冻结 CLIP [CLS] token 为：

$$
\mathbf{f}_i^t
\in
\mathbb{R}^{C\times 1}.
$$

先计算区域内每个 token 与教师 [CLS] 的相似度，再进行 softmax 加权：

$$
\overline{\mathbf{f}}_i^s
 =
\operatorname{SoftMax}
\left(
\cos
\left(
\mathbf{f}_i^s,
\mathbf{f}_i^t
\right)
\right)^{\mathsf T}
\mathbf{f}_i^s.
$$

其中 $\overline{\mathbf{f}}_i^s\in\mathbb{R}^{1\times C}$。这个过程可以理解为：

- crop 的 [CLS] 告诉模型“这个区域整体是什么”；
- 区域内更像该 [CLS] 的 token 获得更大权重；
- 加权后的一个区域向量再与教师 [CLS] 对齐。

内容蒸馏项为：

$$
\mathcal{L}_{\mathrm{content}}^{\mathrm{V\!-\!L}}
 =
\frac{1}{k}
\sum_{i=1}^{k}
\left[
1-
\cos
\left(
\overline{\mathbf{f}}_i^s,
\mathbf{f}_i^t
\right)
\right].
$$

### 6.3 RCC：防止局部对齐把 dense 关系抹平

直接把每个区域压成一个 crop [CLS] 方向，可能增强区域分类，却破坏区域内部 patch 之间原本的关系。于是 DeCLIP 从 VFM 中提取同一 crop 内部的 feature correlation。

对第 $i$ 个区域：

$$
\mathbf{R}_i^{\mathrm{VFM}}
 =
\cos
\left(
\mathbf{f}_i^{\mathrm{vfm}},
\left(\mathbf{f}_i^{\mathrm{vfm}}\right)^{\mathsf T}
\right),
$$

$$
\mathbf{R}_i^{\mathrm{CLIP}}
 =
\cos
\left(
\mathbf{f}_i^s,
\left(\mathbf{f}_i^s\right)^{\mathsf T}
\right).
$$

RCC 用 KL 散度对齐两种区域内部关系：

$$
\mathcal{L}_{\mathrm{content}}
 =
\frac{1}{k}
\sum_{i=1}^{k}
\left[
1-
\cos
\left(
\overline{\mathbf{f}}_i^s,
\mathbf{f}_i^t
\right)
+
\operatorname{KL}
\left(
\mathbf{R}_i^{\mathrm{VFM}},
\mathbf{R}_i^{\mathrm{CLIP}}
\right)
\right].
$$

所以 Content Distillation 内部其实同时包含两件事：

$$
\text{局部视觉—语言对齐}
+
\text{区域内部关系保持}.
$$

## 7. 总损失与训练—推理边界

DeCLIP 的总损失为：

$$
\mathcal{L}_{\mathrm{total}}
 =
\mathcal{L}_{\mathrm{content}}
 +
\lambda
\mathcal{L}_{\mathrm{context}}.
$$

默认 $\lambda=0.25$。

### 7.1 训练阶段

训练时的完整链路是：

$$
\text{无标签图像}
+
\text{随机 crop}
+
\text{冻结 CLIP 教师}
+
\text{冻结 VFM}
+
\text{冻结 Stable Diffusion}
\rightarrow
\text{两条蒸馏损失}
\rightarrow
\text{更新学生 CLIP 视觉编码器}.
$$

冻结教师不是没有参与，而是只提供参照，不接受梯度：

| 分支 | 作用 | 参数是否更新 |
|---|---|---|
| 学生 CLIP 视觉编码器 | 学习新的 dense representation | 是 |
| CLIP 教师 | 给 crop 提供 [CLS] 语义参照 | 否 |
| VFM | 提供 token 之间的语义/空间关系 | 否 |
| Stable Diffusion | 提供边界和物体完整性线索 | 否 |
| 文本编码器 | 提供下游类别文本 embedding | 按实验设置使用 |

### 7.2 推理阶段

DeCLIP 适配完成后，推理不再运行蒸馏教师链。以训练免费 OVSS 为例：

$$
I
\xrightarrow{\mathrm{DeCLIP}}
\mathbf{X}_{\mathrm{dense}}(p),
\qquad
c
\xrightarrow{\mathrm{text\ encoder}}
\mathbf{t}_c,
$$

$$
\operatorname{score}(p,c)
 =
\cos
\left(
\mathbf{x}_p,
\mathbf{t}_c
\right).
$$

低分辨率的 patch-level score map 再上采样到原图大小：

$$
\widehat{M}_c
 =
\operatorname{Upsample}
\left(
\operatorname{score}(\mathbf{X}_{\mathrm{dense}},\mathbf{t}_c)
\right).
$$

因此，论文可以在下游报告 training-free OVSS，但这条测试链使用的是“已经经过无监督微调的 DeCLIP”，而不是原始 CLIP。

## 8. DeCLIP 到底是不是一个“能做很多工作的模型”？

DeCLIP 更准确地说是一个增强后的视觉骨干，而不是单独完成所有任务的分割器。论文把它替换进 F-ViT、OV-DQUO、CAT-Seg、OpenMask3D、CLIP-VIS 和 Oryon 等下游方法，再比较替换前后的结果。

因此，“多任务能力”指同一个 dense-perception backbone 可以被多个下游任务复用：检测和分割依赖局部判别性，3D/视频任务依赖跨视角或跨帧的稳定特征，6D 姿态任务依赖局部结构。性能提升主要归因于 dense representation 改善，而不是新增了一个专用分割 head。

## 9. 实验设置与结果

### 9.1 DeCLIP 预适配设置

| 项目 | 论文设置 |
|---|---|
| 预适配数据 | COCO2017 training set，约 118k 张图像 |
| GPU | 8 张 |
| batch size | 每卡 2 |
| 训练轮数 | 6 epochs，约 20 分钟/epoch |
| 优化器 | AdamW |
| learning rate | $1\times10^{-5}$ |
| weight decay | 0.1 |
| 默认 VLM | EVA-CLIP |
| 微调范围 | 默认微调全部 encoder layers |
| 数据增强 | 未使用，论文报告增强会降低性能 |
| 默认 VFM | DINOv2 ViT-B/L with registers |
| CLIP / VFM 输入 | 例如 CLIP 560、DINOv2 490，使两者都得到 1225 个 image tokens |
| SD 模型 | Stable Diffusion v2.1 |
| SD attention | 50 个时间步中的第 45 个时间步 |
| context loss 权重 | $\lambda=0.25$ |

这里的 1225 个 token 对齐很关键。CLIP 使用 patch size 16，DINOv2 使用 patch size 14，所以不是把两张输入图像简单设置成相同分辨率，而是选择不同分辨率让 patch 数量一致。

### 9.2 OV detection

指标是 OV-COCO 新类别的 $\mathrm{AP}_{50}^{\mathrm{Novel}}$，以及 OV-LVIS 稀有类别的 $\mathrm{mAP}_r$。

| 下游方法 | backbone | OV-COCO | OV-LVIS rare |
|---|---|---:|---:|
| F-ViT + DeCLIP | ViT-B/16 | 43.3（相对 F-ViT + CLIP 提升 5.7） | 27.1（提升 1.8） |
| F-ViT + DeCLIP | ViT-L/14 | 50.2（提升 5.9） | 37.8（提升 2.9） |
| OV-DQUO + DeCLIP | ViT-B/16 | 47.3（提升 8.1） | 31.5（提升 1.8） |
| OV-DQUO + DeCLIP | ViT-L/14 | 49.5（提升 3.9） | 41.5（提升 2.2） |

这些结果的解读是：DeCLIP 改善的是 backbone 的 dense representation，检测器本身并没有被重新设计。

### 9.3 OV semantic segmentation

## 10. 消融：每个模块究竟贡献了什么？

### 10.1 模块递进消融

论文以 MaskCLIP 为起点，报告 OV-COCO 新类别检测、VOC21 和 COCO-Object 的 training-free OVSS：

| Content Distill. | Context Distill. | RCC | SD-GSC | OV-COCO | VOC21 | COCO-Object | Avg. |
|---|---|---|---|---:|---:|---:|---:|
|  |  |  |  | 17.5 | 43.4 | 20.6 | 27.2 |
| ✓ |  |  |  | 37.6 | 42.3 | 23.2 | 34.4 |
|  | ✓ |  |  | 37.4 | 59.7 | 36.4 | 44.5 |
| ✓ | ✓ |  |  | 41.1 | 59.9 | 36.5 | 45.8 |
| ✓ | ✓ | ✓ |  | 42.5 | 60.5 | 36.9 | 46.6 |
| ✓ | ✓ |  | ✓ | 41.9 | 63.7 | 38.5 | 48.0 |
| ✓ | ✓ | ✓ | ✓ | 43.3 | 64.1 | 38.7 | 48.7 |

最清楚的读法是：

- Content Distillation 对检测提升很大，但单独对分割帮助有限；
- Context Distillation 对检测和分割都有效，尤其提升空间一致性；
- RCC 防止内容对齐破坏区域内部关系；
- SD-GSC 在已有 context signal 上进一步补全边界和物体内部，带来额外增益；
- 完整方案同时获得局部判别性和空间一致性。

### 10.2 VFM 与 SD 的合作方式

论文比较了三种组合方式：

| 方式 | VOC20 | Context59 | Cityscapes | ADE | COCO-Stuff |
|---|---:|---:|---:|---:|---:|
| Feature Concat | 75.2 | 30.6 | 24.4 | 19.2 | 19.9 |
| Weighted Feature Concat | 84.4 | 39.1 | 33.7 | 21.7 | 25.1 |
| DirectAlign SD attention | 79.6 | 32.0 | 28.5 | 18.0 | 21.3 |
| SD-GSC | 85.3 | 41.6 | 35.7 | 23.1 | 26.8 |

这说明 SD-GSC 的重点不是把两个模型的 feature 粗暴拼接，而是让 VFM 继续承担语义亲和，SD attention 只作为完整性修正。

### 10.3 VFM 选择与骨干稳健性

论文测试了 SAM、DINO、DINOv2 及不同规模的 VFM。总体上，DINOv2 的语义对应能力最好，DINOv2-B 在综合表现上最优；DeCLIP 在 EVA-CLIP 和 OpenAI-CLIP 上都能保持提升。

## 11. 论文结果、推断与研究假设要分开

### Evidence：论文直接给出的信息

- CLIP 深层图像 token 会集中关注少数 proxy tokens；
- CLIP dense feature 因此缺少局部判别性和空间一致性；
- DeCLIP 将最后自注意力拆成 context 与 content 两部分；
- context 分支对齐 VFM 的 token 关系，并使用 SD-GSC 补全语义亲和图；
- content 分支对齐 crop 的 [CLS]，并用 RCC 保持区域内部关系；
- 训练阶段更新学生 CLIP 视觉编码器，推理阶段不再运行教师蒸馏链；
- 在检测、分割、3D、视频和 6D 姿态任务中，替换 CLIP backbone 后均有提升。

### Inference：基于结构的解释

- Context Distillation 主要修复“相关 token 之间不再互相参考”的问题；
- Content Distillation 主要修复“局部 token 与视觉—语言语义对不上”的问题；
- 论文把两者分开，是因为直接在同一 feature 上同时优化空间关系和 V-L 对齐会产生优化冲突；
- VFM 与 SD 不是两个平行的语义教师：前者提供“像不像同一语义区域”，后者提供“区域是否完整、边界是否连续”。

### Hypothesis：对水下 training-free OVSS 的可检验启发

DeCLIP 本身不是严格 training-free 方法，但它提供了一个很清楚的误差分解：

$$
\text{最终分割质量}
\approx
\text{候选区域质量}
\times
\text{区域视觉表征质量}
\times
\text{文本匹配稳定性}.
$$

对当前 E2O 方向，可以形成以下实验假设：

1. 若 SAM2 已经给出正确区域，DeCLIP 风格的 dense backbone 可能改善区域—文本分类；
2. 若 SAM2 漏掉目标或边界严重错误，改善 CLIP feature 不能恢复不存在的候选区域；
3. 在严格 training-free 约束下，不能在水下图像上执行 DeCLIP 式参数更新；
4. 可以把公开的 DeCLIP 权重当作一个预先适配好的冻结 backbone，与原始 CLIP、SCLIP 或 ClearCLIP 做对照；
5. DeCLIP 的“多种教师、分开约束”更适合作为误差分析框架，不能直接等价为 E2O 中的一个无参数模块。

对 E2O 最小可测的对照是：

| 组别 | 区域来源 | 视觉 backbone | 参数更新 |
|---|---|---|---|
| A | 固定 SAM2 mask | 原始 CLIP | 无 |
| B | 固定 SAM2 mask | 公开 DeCLIP | 无 |
| C | 固定 SAM2 mask | SCLIP / ClearCLIP | 无 |

所有组固定候选区域、类别词、后处理和测试子集，只比较区域级相似度、mIoU、mAcc、aAcc 与推理时间。这样才能分辨提升来自区域质量，还是来自 dense visual representation。
