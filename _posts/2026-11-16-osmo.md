# OSMO：Open-Vocabulary Self-eMOtion Tracking

原论文：[OSMO: Open-Vocabulary Self-eMOtion Tracking](https://osmo-emos.github.io/)（CVPR 2026）。论文提出的是 **OSMO Dataset + OSMO Benchmark + OSIRIS 模型**，三者分开理解。

> **一句话总结：** 从智能眼镜的第一人称视频、音频、眼部信号、对话及个体情绪历史中，持续追踪**佩戴者自己的情绪**，而非像普通表情识别那样只看别人脸上的表情或给短视频打单个类别。

### 术语校准

- 在 [E2O-整理版](/lun-wen-bi-ji/e2o/) 这类 OVSS 里，Open-Vocabulary 是**推理词汇表可动态指定**；标准 benchmark 可以仍然使用固定的 GT 类别表。
- OSMO 的开放词汇主要体现在**情绪标签可以是自由的细粒度自然语言词**，而不是只从 Ekman 六类等封闭分类法中选一种。数据集最终包含 **1,027 种情绪表达**。
- **Zero-Shot** 关心目标任务/类别是否有专门监督，**Training-Free** 关心下游方法是否额外优化模型参数；OSIRIS 用人工标注和自动生成的推理监督进行了 **LoRA 微调**，因此不能当作免训练模型。
- OSMO 评估的是情绪**类型、强度、时间、理由**，不是视觉语义分割的像素掩码。相同的 Open-Vocabulary 词汇，不代表相同的输出空间。

## 1. 研究问题：为什么普通情绪识别不够？

传统 MER（Multimodal Emotion Recognition）常在电影、表演、社交短视频上判断一个人的情绪。智能眼镜的情况不同：

1. **摄像头看到的是佩戴者眼前的世界**，往往看不到佩戴者自己的脸。
2. 情绪是**连续状态**，今天刚被打击后的沮丧可能持续影响下一段对话。
3. 语句含义依赖**对话上下文和语气**：一句“真棒”既可能真高兴，也可能在讽刺。
4. 环境、眼动、声音、历史情绪之间要互相验证，不能看到一个笑脸或听到笑声就机械推断“开心”。
5. 目标是**可解释的时间线**，不仅是某段视频的独立标签。

这属于 **egocentric perception / affective computing** 与具身感知的交叉；**没有机器人动作规划、VLA 控制或导航任务**。

## 2. OSMO Dataset：用现成第一人称数据做人类情绪标注

### 2.1 数据来源及规模（原论文 Table 1）

作者复用 **EgoLife、Nymeria、Aria Everyday Activities（AEA）** 三套已有第一人称长时录制数据，而非为了这项研究从头采集全部视频。

- 原始录制 **约 750 小时**；最终 OSMO 约 **110 小时**。
- **116,100** 条 annotation，**23,200** 个带时间边界的 segment，**288** 个主体。
- **1,027** 个开放词汇情绪术语；**中文 58.7%**、**英文 41.3%**。
- 情绪时长平均约 **7.7 秒**；强度：low **60%**、medium **32%**、high **8%**。

“116K 条标注”并不是“116K 条完整独立视频”；不同数量对应标注条目和片段。

### 2.2 三阶段人机协同标注（论文 Figure 3）

**Stage 1 — 多模型预筛选**
- 使用 Whisper 从原始流提取时间戳转写，切成约 **200K** 个话语片段。
- Emotion-LLaMA、AffectGPT、DeSTA2.5-Audio、Qwen2-Audio 分别给基础情绪/中性类别作预测。
- 至少 **3 个模型**同意是非中性情绪的片段才优先保留，得到约 **17.8K** 个候选，扩成 30 秒上下文后约 **125 小时**供人工审核。

这一步模型主要做**候选情绪片段筛选**，不是直接确定最终细粒度 GT。

**Stage 2 — 人工精标**
- **41 名**标注员，超过 **8,000 人时**。
- 标出主要和次要情绪、正中负倾向、low/medium/high 强度、开始/结束时间，以及基于可观察证据的原因。
- 允许自由使用细粒度情绪词，但辅以 Plutchik 情绪轮等规范指导。
- 第一阶段的模型预测对人工标注员隐藏，降低答案暗示。

**Stage 3 — 模型检查 + 人工复核**
- 检查空缺、过短/过长的时间片段、描述过短、时间边界异常等。
- LLaMA-as-a-judge 质量评分低于 **8/10** 的标注需返工。
- 人工复核类别、时间和原因，报告一致性：**87.0% / 91.2% / 82.6%**。

**非常值得注意**：LMM 的预筛候选有 **88.0%** 被人工保留，但模型情绪预测和人工标签仅有 **48.6%** 的重合。也就是说，**找到“这里可能有情绪”远比“准确说出这是什么情绪”容易**。这和水下 OVSS 的“候选区域 vs 类别赋值”很相似。

## 3. OSMO Benchmark：五个任务与四种泛化划分

| 任务 | 要预测的东西 | 主要指标 |
|---|---|---|
| **OVER** Open-Vocab Emotion Recognition | 佩戴者的开放词汇情绪 | SOS（集合重合度）、HR（命中率） |
| **SA** Sentiment Analysis | positive / negative / neutral | Accuracy、加权 F-score（WAF） |
| **IP** Intensity Prediction | low / medium / high | Accuracy、WAF |
| **EL** Emotion Localization | 情绪开始、结束时间 | 时间 IoU/mIoU、$R_{n,U}@m$ |
| **ER** Emotion Reasoning | 基于上下文解释情绪来源 | BLEU、ROUGE-L、METEOR；LLM Judge 的 IC/DO/CU/TUC |

四种数据划分分别评估不同泛化能力，**不是四个新增任务**：
- **XSub**：训练/验证参与者身份互斥，跨人泛化。
- **XTime**：训练/验证录制日期互斥，跨天泛化。
- **XLang**：中文、英文及两个方向的跨语言迁移。
- **XSet**：用保留的 AEA 子集进行跨数据源测试。

所以 OSMO 不仅是一堆视频和标签，**它提供了完整的任务定义、数据划分、指标和模型基线**。

## 4. OSIRIS 架构：专家编码器 + Adapter + 历史记忆 + LLM

OSIRIS = *Omnimodal Self-emotion Inference with Reasoning on Input Signals*。

可以拆为五个步骤（论文 Figure 5）：

**① Encode：各模态编码**
- 视频（visual context）与眼部红外视频（eye IR）：使用冻结的视觉专家编码器，正文引用的 **[57] 是 DINOv3**。
- 音频：预训练声学模型，提取声调等特征。
- 对话转写：经 LLM 文本嵌入层处理。
- 历史情绪：作为当前输入的个体上下文。

**② Adapt：可训练模态适配器**  
将视频、眼部、音频的不同特征维度映射到统一 LLM 表征空间，便于融合。

**③ Remember：个体情绪记忆**
一个历史情绪事件包含：
- **What**：情绪的自然语言标签；
- **How**：多个模态经门控和 cross-attention 提炼的表达向量；
- **When**：时间戳与持续时间。

记为：
$$
E_i=\{O_i,Q_i,t_i,D_i\}.
$$

每次推理检索近期的情绪词及多模态记忆特征，带入距现在多久、持续多久的信息。它是**情绪事件状态记忆**，不等同于“有聊天记忆的完整 Agent”。

**④ SENSE：先生成多模态结构化 CoT 监督**
SENSE = *Structured Emotional reasoNing from SEnsory inputs*。作者用视频/音频 caption 模型补充感知细节，把**人工情绪标签**、描述、对话和历史情绪送给 LLaMA3，生成六步推理标签：
1. visual scene；2. audio tone；3. dialogue；4. eye cues；5. prior emotion；6. final emotion inference。

这些 CoT 是**训练监督文本**，不证明模型生成的每条解释都与其内部推理完全一致。

**⑤ Predict：LLM 输出情绪与解释**  
使用 LoRA 微调基本 LLM，让它条件化于当前模态 + 记忆并输出结构化情绪解释。整体是**训练过的 LMM**，不是拼接模型后零训练即用。

流程：Video / Eye IR（DINOv3）+ Audio + Dialogue → Adapters → Memory（What / How / When）→ SENSE-supervised LLM → Emotion timeline。

## 5. 核心实验与消融

作者在 XSub、XTime 等协议上比较现有情绪模型。相对**微调的 AffectGPT**，OSIRIS 多指标平均提升约 **+10.7（XSub）**、**+10.1（XTime）**；不要与论文中相对 **zero-shot LLaMA3** 的改进幅度混在一起。

论文 Figure 7 的消融特别能说明贡献位置：

| 改动 | 对参考模型的平均改善 |
|---|---:|
| 加前序情绪标签 | +3.6 |
| 加历史多模态记忆 Query | +6.8 |
| 加对话上下文 | +7.7 |
| 加 SENSE 结构化推理监督 | +8.2 |
| 全部组件联合 | +10.5 |

**不可把这些提升直接相加**；它们是不同实验条件下相对参照的比较。

### 去掉一个模态会怎样？

| 移除模态 | 多指标平均影响 |
|---|---:|
| Dialogue text | **−8.5**（最大） |
| Audio | −6.8 |
| Video | −4.6 |
| Eye IR | −1.6 |

虽然眼部整体影响较小，但移除眼部使**时间定位 mIoU 下降约 3.9**。说明眼部信号可能对时间边界特别有用；**对话文本和语音比纯视觉更加核心**。

### Memory 窗口

论文检验历史条数变化：检索约 4 条近期情绪比不使用记忆更好；增加历史 Query 和对话跨度能继续改善，但逐渐饱和。结论是**适度个体情绪历史有用**，而非无限追加上下文最优。

## 6. 为什么作者不用 OSIRIS 自动完成 OSMO 的标注？

- **先有人工标注的 OSMO，才能监督训练 OSIRIS**。OSIRIS 在训练前不能作为已验证的高精度标注器。
- 将模型自己预测的标签作为独立测试集 GT、再评价同一个模型，会产生循环验证与偏差放大。
- 情绪属于隐含的主观状态：仅凭旁观者看到的场景不一定能确定佩戴者是开心、讽刺还是尴尬。
- 文章已经实际使用 LMM **预筛**与质量审查；模型标签和人工情绪标签 48.6% 重合说明**让模型直接接管精标仍不可靠**。

后续确实可以用 OSIRIS 对未标注数据做 active learning / pseudo-labeling，但必须保留独立人工 GT，并测新增标注可靠性。

## 7. 与 Catch Your Emotion 和具身智能的关系

**Catch Your Emotion** 研究图像级 MLLM 的细粒度情绪分类、视觉 Token 选择；OSMO 研究的是佩戴者**自己的连续多模态情绪**。方法交集主要在细粒度情绪判别，但无法把对方的图像推理模块直接当作 OSMO 完整标注器。要适配音频、对话、眼部和时间记忆。

OSMO 是 **egocentric + affective + multimodal**，确实和具身感知有交集；但**不研究导航动作、策略学习、VLA 控制**。如果把“具身”笼统理解成所有第一人称感知论文，领域就会显得极其分散。

## 8. 我的评价及对科研的启发

**贡献分为三层：**
1. 新任务：把独立的情绪分类变成可解释、按时间变化的第一人称情绪追踪。
2. 新数据/评测：复用 750h 原始视频并投入 8,000+ 人时建立 110h 可靠标注，定义五任务四协议。这是**高人力门槛**贡献。
3. 系统模型：DINOv3、音频编码器、Adapter、LLM 属于模块集成；真正具有针对性的设计是**个体情绪记忆 + SENSE**，其必要性由消融支撑。

**仍存疑问：** 真实主观情绪是否能由外部可观察信号作为可靠 GT？不同语言对应主体的分布差异是否影响跨语言结论？SENSE 的 LLM 解释有多大程度与实际因果事件一致？

对 [E2O-整理版](/lun-wen-bi-ji/e2o/) 的直接启发不是做一模一样的数据集，而是：
- 分开研究候选检出和准确赋类；
- 用人工 GT 校验自动系统的高置信错误；
- 清楚区分 Dataset、Benchmark 和 Model 的创新；
- 在有资源限制的小团队，更可能选择**明确的可复现方法问题**而不是重新做大型情绪标注。

**最后一句：OSMO 不只是“DINOv3 + LLM”，它真正的重心是新任务与大规模标准化标注；OSIRIS 是验证连续情绪追踪可行性的多模态模型。**
